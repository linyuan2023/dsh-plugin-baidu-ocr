## 0. "完美复刻"的定义、度量与天花板

复刻拆成五层，逐层可度量：

| 层 | 含义 | 度量方式 |
|---|---|---|
| L1 内容完整 | 一字不丢、一字不多 | 产物文本 vs 原件文本层的归一化编辑距离 / 覆盖率 |
| L2 结构正确 | 阅读顺序、块类型（标题/段落/表格/图/公式） | 块序列人工比对 + golden 快照 |
| L3 几何保真 | 页数、页面尺寸/方向、栏式、块位置 | 页数一致、页宽高一致、content-list bbox vs 原件块矩形的 IoU |
| L4 样式保真 | 字号/字体/标题层级/表格线/行距 | 字号估计误差、标题分级正确率（golden 人工判定） |
| L5 视觉保真 | 渲染结果与原件对照 | 渲染页与原件页并排/叠差人工评审（golden 内） |

**天花板（必须诚实面对，决定各格式的"完美"标准不同）：**
- 百度 VL 后端只给 `text + position + polygon + type`（docs/layout-improvement-analysis.md §8.1），
  **字体/字号/颜色/线宽根本不在后端响应里**——L4 只能从几何反推（position 高度→字号），有上限。
- **扫描件**：L5 可以真正做到 100%——原页位图本身就是原件（sandwich PDF 路线，见 5.0.2）。
- **数字原生 PDF**：原件即复刻；插件的价值在 L1–L3 + 可编辑产物。
- **docx**：定位是"可编辑复刻"，完美标准 = 页数一致 + 结构正确 + 样式近似，永远到不了像素级；
  **pdf（复刻模式）**：扫描件下像素级可达。
- AI Studio 后端只给 markdown（无坐标）——走该后端时 L3–L5 无从谈起，
  这是"AI Studio 矢量图册无图"问题的本质：**是复刻失败，不只是 UX 问题**。

## 1. 现状差距盘点（代码证据）

## 2. MinerU 在复刻北极星下的剩余价值

- **仍借**：hybrid 页级混合思想（L1 完整性）、跨页段落/表格合并（L1/L2）、
  content_list 归一化 bbox 格式（L3 度量的底座）、"每个版本报基准分"的评测方法论（OmniDocBench 之于 MinerU ≈ 复刻度评分之于本插件）、fallback 可靠性（复刻失败自动补救）。
- **不再借**：tier/effort 档位化（UX 项，与复刻无关，降为可选）、Office 本地直读（速度/成本项，
  且数字原生文档本就不该走 OCR——移出主线）、流式落盘（UX 项，降为顺手）、/ocr lib（移入远期）。

## 3. 路线图（重排后）

### v0.4.0 「内容完整性与护栏」（5–8 人日）

L1 是复刻的地基：内容不完整，后面全是空中楼阁。

- **4.0.1 golden 回归集**（同 v1 方案）：脱敏真实版面 JSON ≥8 份 + 产物快照 diff，`UPDATE_GOLDEN=1` 刷新。
  升级点：快照断言从"md 对不对"扩展为"块序列 + 页数不回归"。
- **4.0.2 页级 hybrid（检测先行）**（同 v1 4.0.4 第一步）：直取后 thin 页列进 note。零风险。
- **4.0.3 跨页段落合并**（同 v1 4.0.3）：保守句读判定 + `paraMerge` 独立开关，三处拼接点接入。
- **4.0.4 EXIF 方向修正**（同 v1 4.0.2）：只修判断层。
- **4.0.5 fallback 的复刻化重述**：AI Studio 结果"markdown 无图片占位且无 layoutJson"检测 →
  note 明确"本结果无法用于版面复刻，请切智能云重跑"（比 v1 的 UX 话术更强）。

### v0.5.0 「复刻主攻：度量 + 几何 + 视觉」（10–13 人日）★核心版本

- **5.0.1 docmodel 最小版 + content-list 输出**：`lib/docmodel.js`
  （pages[].blocks[]，bbox 归一化 0–1000，坐标来自 layout position/polygon）；
  `--content-list` 格式落盘。**它是 L3 度量的底座**，从 v1 的 0.5.0 提前并瘦身
  （不收敛全部导出器，只做伴随产出）。
- **5.0.2 复刻度评分 `lib/fidelity.js`**（新增，本计划的心脏）：
  数字 PDF 用 pymupdf 抽原件 ground truth（每页词序列、块矩形、页宽高、图片数），
  与 content-list 对比产出 `replicaScore { textCoverage, blockIoU, pageMatch, imageCount }`，
  在工具返回 note 与 `/ocr` 输出中显示；golden 回归加"分数不低于基线"断言。
  从此每次改动都能量化"离完美近了多少"——对齐 MinerU 每版报 OmniDocBench 的做法。
- **5.0.3 sandwich PDF（扫描件复刻旗舰）**：新格式 `--pdf-replica`——
  原页 pymupdf 高 DPI 位图打底 + VL 文本按 bbox 以隐形文字层（pymupdf `render_mode=3`）叠加
  → **视觉 100% 复刻 + 全文可检索可复制**。数字 PDF 检测到全文本层时提示"原件即复刻"。
  与现有 html.js 流式路径并存（`--pdf` 保持"可读文档"定位，`--pdf-replica` 是"复刻"定位）。
- **5.0.4 docx 页面几何钉死**：`sectPrXml`（ooxml.js:344）从原件读页宽高
  （pymupdf 页尺寸 pt→twips，1pt=20twip），边距由内容 bbox 推算——非 A4 原件（16开/B5/图纸）分页不再漂移。
- **5.0.5 字号/行距传递**：正文块也按 position 行高估字号（不止标题），html.js 与 docx
  按估计值输出、预设体系降为回退；行距按行间隙估计。L4 的主要得分点，golden + 评分双重护栏。

### v0.6.0 「结构保真深化」（6–9 人日）

- **6.0.1 表格真嵌套**：docx `w:tbl` 嵌套替代降级摊平（L2/L4）。
- **6.0.2 3+ 栏与复杂栏式**：orderLayouts 从双栏启发式泛化（L3）。
- **6.0.3 表注吸附**：对齐已有图注吸附（"表x-x"与表格绑定）。
- **6.0.4 竖排/旋转文本评估**：polygon 已有数据，先评估后端是否输出此类块再定实现。
- **6.0.5 fallback 自动化**（v1 7.0.1 提前且重述理由）：矢量图册类复刻失败自动切智能云重跑，默认 off。

### v0.7.0 「远期」

- 7.0.1 /ocr lib 文档库 + `ocr://id#page=N` 稳定引用（依赖 content-list）。
- 7.0.2 隐私与数据流向说明。
- 7.0.3 mineru.net 第三后端（预研后定；理由=内容层复刻兜底：表格/公式识别更准）。
- 7.0.4 tier/effort 档位化、分段流式落盘、Office 本地直读（v1 主线项全部降级至此，
  按需捞回）。
