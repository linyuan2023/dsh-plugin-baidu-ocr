# 竖排/旋转文本支持评估（v0.4.0 §3.14，仅评估不实现）

日期：2026-10-15 · 结论：**暂不实现，等真实样本**

## 现状

- 百度 VL 版面 JSON 的 layouts 块带 `polygon`（四点）与 `position[x,y,w,h]`（轴对齐包围盒）。
  实测样本（476 页图册、公文、论文）中未出现竖排块；`type` 枚举里无 vertical 类。
- 插件现有管线全部按轴对齐假设处理（阅读顺序按 y/x 排序、bbox 归一化、隐形文字层按矩形叠加）。

## 要支持需要什么

| 环节 | 工作量 | 说明 |
|---|---|---|
| 检测 | 小 | polygon 两邻边不垂直/宽高比异常时标 `vertical: true` |
| 阅读顺序 | 中 | 竖排块（传统中式右→左）需独立成列处理 |
| docx | 大 | 需 textDirection/旋转文本框，现有 w:p 流式渲染不支持 |
| sandwich PDF | 中 | pymupdf insert_textbox 无旋转；需 TextWriter + morph 旋转矩阵 |

## 触发条件（满足其一再立项）

1. 真实用户样本中出现竖排/旋转块且识别质量可接受（后端给了文本）；
2. 百度后端枚举出现 vertical 类类型（届时仅需打通 docx/PDF 两处渲染）。

在此之前，若后端输出竖排块，现有管线按普通横排块处理——内容不丢（L1 完整性不受影响），
仅顺序/样式可能不对（L2/L4 局部降级），可接受。
